# Phase 26: Writing Tests (Unit & Integration)

## Overview
This phase introduces an automated testing suite across our polyglot microservice backend, ensuring regression safety as the platform scales. By capitalizing on the clean architecture implemented in Phase 25, we established isolated testing environments without requiring active database connections or message broker clusters.

## Golang (`service-scraper`) Unit Testing
Leveraging the `EventPublisher` interface, we successfully mocked the Kafka pipeline using a `MockPublisher`. The testing suite creates an in-memory slice that captures output from `Publish()`, allowing us to assert that the `DBJob` struct is correctly marshalled and generated by the scraping logic, decoupled from network IO.

## Python FastAPI (`service-resume`) Integration Testing
We implemented `pytest` alongside FastAPI's native `TestClient` to perform integration tests on the `/parse` endpoint.
1. We successfully asserted that the API appropriately enforces content negotiation, rejecting non-PDF payloads with a 400 Bad Request.
2. We mocked the internal `PyPDF2.PdfReader` to assert that a simulated PDF payload is correctly consumed, resulting in a 200 OK containing the expected `filename`, `status`, and `extracted_skills` array.

## NestJS (`service-user`) Unit Testing
Using Jest, we provided a mocked `UserRepository` (created during our Phase 25 refactor) and a mocked `ClientGrpc` representation of `RESUME_PACKAGE` to the `Test.createTestingModule`. We isolated the `UserService` and asserted that `findOrCreateUser` successfully triggers the underlying PostgreSQL repository mock with identical arguments, avoiding any actual network bounds.
